# GHOSTTRACE — Ultimate Enhancement Plan (v0.2 → v1.0)

Written 2026-11-15. Baseline: everything in `docs/upgrade-plan.md` is DONE (git, tests 34 backend + frontend suite, CI on CircleCI/Bitrise/Codemagic, Smarter Testing, Google+ActivityWatch+Wazuh+GitHub integrations, Gmail alert classification with device/location/app extraction, iOS+Android sources, deployment stack).

Goal: turn a solid personal-OSINT dashboard into a top-tier self-monitored intelligence platform. Phases ordered by user-visible value; each phase ships something real.

Legend: [BE] backend · [FE] frontend · effort in dev-days (focused solo, using the beam-free workflow to parallelize)

---

## Phase 1 — Real-time core (BE ~5d, FE ~4d)
Everything downstream feels instant; no more "check the page later".

| # | Feature | Spec / acceptance |
|---|---------|-------------------|
| 1.1 [BE] | **WebSocket event stream** | `GET /ws/events` authenticated via JWT in query (or first-message token); broadcasts every ingested event + alert to that user's connections. Fan-out via in-process pub/sub (single worker) behind an interface so Redis pub/sub is a drop-in later. Test: ws client receives an event created via API. |
| 1.2 [BE] | **Webhooks on ingest** | Per-user webhook rules (url, event filter) in new `webhook` table; async dispatch with retry/backoff; recorded in audit log. |
| 1.3 [FE] | **Live timeline + toast alerts** | subscribe on dashboard mount; new `security.*` events trigger toast + "12 new events" pill on timeline; optimistic insert without poll. |
| 1.4 [BE] | **Full-text search** | SQLite FTS5 (mirror table `events_fts`) / PG `tsvector` alternative; `GET /api/v1/events?q=` switches to index-backed search. Pagination + highlight offsets. |
| 1.5 [BE] | **IP geolocation enrichment** | at Gmail login-alert ingestion: resolve `ip` → city/country via ip-api.com (free tier, no key) with local cache table; store `geo` in metadata; flag unknown/unreachable. |
| 1.6 [FE] | **Command palette** | ⌘K / Ctrl+K: navigate, search events, trigger syncs, toggle sources. (cmdk lib, keyboard a11y.) |

**Gate:** live demo — trigger an OAuth grant on the Gmail account, alert appears on the dashboard < 2 s.

## Phase 2 — Data breadth (BE ~10d, FE ~3d)
The dashboard is only as good as its feeds. All sources follow the existing BaseIntegration + capability-honesty pattern (no fabrication, explicit `permission_status`).

| # | Feature | Spec / acceptance |
|---|---------|-------------------|
| 2.1 [BE] | **Breach monitoring** | new `breach` integration: HIBP v3 (`/breachedaccount`, requires API key env `HIBP_API_KEY`) + DeHashed optional; store `account.breach` events; UI page listing compromised accounts/services; MFA-gated email input. |
| 2.2 [BE] | **Export parser library** | `app/services/parsers/`: Instagram (JSON), Facebook (JSON zip), Telegram (`result.json`), WhatsApp (txt/csv), Google Takeout (already), Apple (iOS+Watch `*.json` from an Apple Privacy export). Each parser normalizes into events with dedup keys; upload endpoint per format reusing the takeout importer pattern. |
| 2.3 [BE] | **Microsoft account** | MS Graph via OAuth device-code flow (client id from env): sign-in logs (`/auditReports`), mailbox usage. Capabilities honest about personal vs Entra accounts. |
| 2.4 [BE] | **Network monitoring** | poll router via SNMP (`pysnmp`) or scrape **Pi-hole/AdGuard Home API** (user has AdGuardHome installed on this machine — direct integration): `network.device_seen`, DNS-blocked event stream. Config: base_url + token. |
| 2.5 [BE] | **Calendar aggregation (multi-provider)** | extend CalendarCollector's server-side twin: pull ICS URLs directly (Apple/Google/Outlook share links) via `ical` parsing, so calendar coverage doesn't require the phone app. |
| 2.6 [BE] | **Password-rotation reminders** | `security.rotation_due` events generated by scheduler from audit history of recovery/password-change alerts (30/60/90-day thresholds). |
| 2.7 [FE] | **Source catalog page** | grid of all integrations with status, last-sync, event-count sparklines; per-source detail route (`/integrations/[kind]`). |

**Gate:** a new user can connect ≥ 4 sources and see distinct, correctly-deduplicated timelines.

## Phase 3 — Intelligence layer (BE ~8d, FE ~4d)
From "what happened" to "what it means".

| # | Feature | Spec / acceptance |
|---|---------|-------------------|
| 3.1 [BE] | **User risk score** | rolling 0–100 score per user: weights (active breaches, unacked alerts, unusual login velocity, stale recovery info, failed syncs). Recomputed on scheduler tick; stored with history for charting. `/insights` returns score + drivers. |
| 3.2 [BE] | **Impossible-travel detection** | on login_alert events with geo: flag pairs < 4h apart with > 500 km delta as `anomaly.impossible_travel` (haversine; home-city baseline inferred from most-frequent location). |
| 3.3 [BE] | **Sigma-style rule engine v2** | upgrade current flat rules: AND/OR condition groups, field operators (`contains`, `gt`, `since`), rule versioning + `enabled` at-event-time evaluation in a new `detections` service. Keep old rules auto-migrated. |
| 3.4 [BE] | **Cross-account correlation graph** | compute edges (same device, same time-window, same IP) between event clusters; expose `/api/v1/graph` (nodes+links) with a cap on edges. |
| 3.5 [BE] | **Optional local AI summarizer** | `ollama` integration (user already has .ollama dir): daily digest "what your day looked like + 3 things to check" — feature-flagged, never required, data stays local. |
| 3.6 [FE] | **Risk dashboard** | score gauge, 30-day trend, driver breakdown; alert feed with ack/dismiss wired to the real API. |
| 3.7 [FE] | **Graph view + time slider** | vis-network for correlations; map gains time-range slider + clustering. |

**Gate:** seeded test dataset produces a non-trivial risk score and one impossible-travel alert end-to-end.

## Dependencies & constraints
- Phase 1 → everything (real-time bus); Phase 3 depends on 1.5 (geolocation).
- GitHub Actions still billing-locked → Bitrise/Codemagic absorb CI additions.
- iOS real-device test needs Mac access; not a blocker for v1.0 (USB-free Gmail path already covers device-activity signal).
- All new secrets via `.env` + `config.py`; never committed.

## Suggested order for maximum visible impact
1. **Phase 1** first (feels magical, small)
2. Phase 2.1 + 2.4 (breach monitor + AdGuard Home — you already run AdGuardHome, instant win)
3. Phase 3 (risk score is the "OSINT platform" centerpiece)
4. Phase 4 in parallel with 3 (FE agents independent)
5. Phase 5/6 last

Estimated total: ~55–60 dev-days compressed into ~6–8 weeks part-time; the dynamic-workflow pattern used for the last upgrade can execute any phase here directly.
